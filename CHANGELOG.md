## [Unreleased]

### Added

- The console design system, written up in `console/design.md`. Tailwind CSS 4 through `@tailwindcss/vite` styles the console from one stylesheet, `src/ui/theme.css`, the only source of token values: OKLCH colors (a cool zinc neutral, an indigo accent, and status colors), system font stacks with a 14 px base, a 4 px spacing grid, and radius, shadow, layer, and motion tokens. Tailwind's default color, font, size, radius, and shadow scales are reset, so `bg-red-500` compiles to nothing, and the build emits one CSS file. `tooling/scripts/design-tokens.mjs` writes the token tables in `design.md` from `theme.css` during `pnpm fix`, and `pnpm check` fails when they are stale. `theme.contrast.test.ts` checks every text token at 4.5:1 and every border, focus, and accent token at 3:1 on every surface, in both themes. (spec 0015 AC-1, AC-2, AC-5, STY-1 to STY-4, TKN-1 to TKN-7; `aad8fbc` (PR 108))
- Themes and density. Theme is System (the default), Light, or Dark, chosen in the account menu or the command palette and stored in `orvano:v1:theme`; `public/theme-boot.js` sets `data-theme` and `color-scheme` before the first paint, and a theme switch never animates. With `prefers-contrast: more`, decorative borders turn strong and muted text turns full strength. In forced colors mode the focus ring, control borders, and a 2 px inline start mark on the current sidebar item, open resource, and current tab stay visible. Density is Comfortable or Compact: `data-density` on `<html>` switches the row height of tables and lists, while forms, the sidebar, and the top bar keep their size. Reduced motion makes slides and scales instant. Browser storage goes through the new `shared/storage` module (`defineStored`), which never throws and follows changes made in other tabs. (spec 0015 AC-4, AC-6, THM-1 to THM-6, MOT-1; `aad8fbc` (PR 108), `628e51b` (PR 110), `e3aaf3f` (PR 117))
- The console shell in `src/ui/shell/`. `AppShell` renders a skip link, a 48 px top bar, breadcrumbs, a primary sidebar for each scope (project, org, account) from the `NavId` registry, and one `main`. The sidebar collapses to a 56 px icon rail with names in tooltips, and below 64rem the sidebar and the resource list become drawers. `Breadcrumbs` marks only the last crumb as the current page and opens `OrgSwitcher` and `ProjectSwitcher`, which search 150 ms after you type, show up to 20 results, and announce the count. `ResourceLayout` and `ResourceList` keep the list beside an open resource, resize by pointer or by keyboard on a separator (200 to 480 px, never squeezing the content below 480 px), collapse to a 40 px strip, and save the layout per service. Also `PageHeader`, `RouteTabs`, `Tabs`, `AccountMenu` (theme, density, keyboard shortcuts, sign out), `useDocumentTitle`, and `AuthLayout`, which frames the pages without the shell and now wraps the welcome page. The real shell routes come with feature 13. (spec 0015 AC-7 to AC-11, AC-21, SHL-1 to SHL-13, spec 0001 UX-2; `aad8fbc` (PR 108), `628e51b` (PR 110), `e3aaf3f` (PR 117))
- Forms and overlays. `useAppForm` in `src/ui/form` is built on TanStack Form: a screen passes default values, a Zod schema, and `onSubmitAsync`, never validator timing. The fields are `TextField`, `PasswordField`, `TextArea`, `NumberField`, `Select`, `Combobox`, `Checkbox`, `CheckboxGroup`, `RadioGroup`, and `Field` for custom controls, with `Form`, `SubmitButton`, `ErrorSummary`, and a standalone `Switch`. A field is checked when it loses focus after a change, then on every change. After a failed submit, focus moves to `ErrorSummary`, server field errors land where client errors do, and the submit button is never disabled for invalid input. The overlays are `Dialog`, `Popover`, `Menu`, and the lazy `SideSheet` and `ConfirmDelete`. `ConfirmDelete` takes its tier from a typed map of resource kinds: tier 1 asks you to type the name, tier 2 starts focus on Cancel, and a bulk delete of more than 1,000 rows asks for the count. It counts dependents first, and a failed delete shows an inline error. `UnsavedChangesGuard`, the only user of the router's blocker, asks one question however many forms changed, a closing sheet included. (spec 0015 AC-16, AC-17, spec 0003 FRM-1, FRM-2, RTE-8, spec 0001 UX-8, UX-9, UX-23; `0919c94` (PR 111))
- Feedback and data display. `notify()` is the one way to raise a message: it feeds the toasts (bottom corner at the inline end, three visible, identical ones merged with a count, success and info closing after 6 s, errors staying until dismissed), the message history (the last 50), and the screen reader announcer. Also `Banner` (one at a time, in the `AppShell` banner slot), `InlineError`, `EmptyState`, `ErrorState`, `Skeleton`, `GridSkeleton`, `ContentSkeleton`, `useDelayedPending` (nothing for 300 ms, then at least 500 ms shown), `Progress`, `Spinner`, `StatusChip` (a label and an icon, never color alone), and `Badge`. For data there are the lazy `Table` (sortable, selectable, row height follows density), `SettingsCard`, `DangerZone`, `CopyField`, `SecretReveal`, `CodeSnippet`, and `RelativeTime`. Where the clipboard is refused, as on plain HTTP, copying selects the value and says how to copy it by keyboard. A boot error page and a root error page, plain token pages with Reload and the request id, render before any session exists. AC-12's list of live regions leaves out `InlineError`, and review findings 11 and 20 would add switcher errors and `ErrorState` to it; those spec edits are owed to `/architect`, together. (spec 0015 AC-12, AC-15, AC-17, AC-21, AC-24; `484eeca` (PR 112))
- Keyboard shortcuts, the command palette, and the docs pane. `useShortcut` is the only way to bind a shortcut: it adds the shortcut to the list `ShortcutHelp` shows on `?`, returns `aria-keyshortcuts` for its visible control, does nothing while a modal is open, and never fires a one character shortcut while you type. `Kbd` shows ⌘ on Apple platforms and Ctrl elsewhere. - The `/v1` wire format in `Orvano.SharedKernel/Api/`. `ApiRoutes` creates the `/v1`, `/v1/projects/{projectId:guid}`, and `/v1/console` groups the modules map into; a project id that is not a uuid answers `404 not_found`, and no `/v1` route redirects. `ApiVersions.Current` is `2026-10-22`: a request without `Orvano-Api-Version` is served as current, and a malformed or unsupported value answers `400 unsupported_api_version` with `supportedVersions`, even on an unmatched path. Every `/v1` response, errors included, carries `Orvano-Request-Id` (the 32 hex trace id), `Orvano-Api-Version`, and `Cache-Control: no-store` unless the endpoint uses `.WithCacheControl(...)`; `OrvanoHeaders` holds every header name. JSON is camelCase with snake case string enums, UTC RFC 3339 timestamps ending in `Z`, and nulls always written. An unknown body property answers `400 validation_failed` with field code `unknown_field`, and names are case sensitive. (spec 0014 AC-3 to AC-6, AC-8; `5ef8e80` (PR 71))
- One problem body for every `/v1` error: `type`, `title`, `status`, `detail`, `code`, `traceId`, then `errors`, `retryAfter`, and any extensions. Framework failures get codes too (`400 invalid_request`, `404 not_found`, `405 method_not_allowed`, 413, 415, `500 internal`, `503 timeout`). `ErrorCodes` is the catalog of codes, `Error` gains `PreconditionFailed` (412) and typed `FieldError`s, and each validation attribute's `ErrorMessage` is a `FieldCodes` value, enforced by an architecture test. - The SDK generator, `@orvano/sdk-generator` in `api/generator/`: TypeScript run by Node 24 with no build step and no runtime dependencies. `generate --target <t> --contract <path> --out <repo>` reads the contract into one model and rewrites only the generated and runtime folders of an SDK repo. There are five targets: `ts-client` (`@orvano/client`), `ts-server` (`@orvano/server`), `dart-client`, `dart-server`, and `csharp-server`. Models leave fields named like tokens, secrets, passwords, or keys out of their text form. The runtime templates are `runtime/typescript/` and `runtime/dart/` (transport, per attempt timeout, retry with backoff or `Retry-After`, problem parsing, and no redirect ever followed; the Dart client runtime compiles with dart2js and dart2wasm), and `templates/csharp/` with `OrvanoWire.cs`, the seam to the runtime written by hand in `sdk-dotnet`. Snapshots are checked by `pnpm test:generator`, `pnpm test:generator:dart`, and `pnpm test:generator:csharp` in CI, and `ORVANO_SNAPSHOT_WRITE=1` rewrites them. (spec 0014 RGN-4, RGN-5, spec 0007 IMG-3, spec 0006 SUP-8; `4350d69` (PR 79))
- Cursor paging. `Page<T>` (`items`, `nextCursor`, `total`) with `Page.From(...)` builds a page from a keyset query fetched with `Take(limit + 1)`. `PageQuery` binds `limit` (1 to 100, default 50, else `out_of_range`) and `cursor` (at most 2048 characters). `CursorCodec` writes `{ v: 1, k, q }` as base64url, and a cursor that doesn't parse, has the wrong key shape, or belongs to another filter, sort, or route answers `400 invalid_cursor`. `.WithPaging(total)` documents it in the contract as `x-orvano-paging`. The SDKs return `Page<T>` with `listAll()` in TypeScript, `ResultPage<T>` with a lazy `Stream<T> listAll()` in Dart, and `ResultPage<T>` with `ListAllAsync()` (`IAsyncEnumerable<T>`) in C#. No real endpoint is paged yet. (spec 0014 AC-10, PAG-1 to PAG-7; `3dca0af` (PR 83), `f11e68c` (PR 95))
- Partial updates and row versions. In a PATCH body, an `Optional<T>` field left out stays unchanged, a sent `null` clears a nullable field (a non nullable one answers `validation_failed` with field code `required`), and arrays and objects are replaced whole. Validate the sent value with `[OptionalValue<TAttribute>(...)]`. `ResourceVersion` is the opaque version, `SetETag` writes a strong `ETag`, and `IfMatch.Check(version)` answers `412 version_conflict` with `currentVersion`; a write with no `If-Match` goes ahead, and `*`, a list, or a weak or unquoted tag answers `400 invalid_request`. `.WithConcurrency()` puts it in the contract. The SDKs send a PATCH's optional fields as `field?: T | null` in TypeScript and `Optional<T>` in Dart and C#, and their `ifMatch` option sends a strong `If-Match`. (spec 0014 AC-9, AC-11, JSW-9, JSW-10, CNC-1 to CNC-5; `d7d62bc` (PR 84), `f11e68c` (PR 95))
- The `Idempotency-Key` wire contract. `.WithIdempotency()` marks an operation (`x-orvano-idempotent` and the header in the contract); on a marked operation a key that is not 1 to 255 printable ASCII characters, or is sent twice, answers `400 invalid_request` before the handler runs, and an unmarked one ignores the header. The SDKs gain an `idempotencyKey` option on marked operations, check its format, and retry a call that is not a GET only when it carries a key. Nothing is marked until the replay store arrives with feature 14 or 16. (spec 0014 AC-12, IDM-1 to IDM-5; `7067938` (PR 85))
- Public events in the contract. `services.AddPublicEvent<TEvent>(description)` registers an `IOutboxEvent` in `IPublicEventCatalog`, and `WebhooksTransformer` writes it into the public document's `webhooks`, keyed by event type, with a body named after the type (`auth.user.created.v1` gives `AuthUserCreatedV1Event`). All five generator targets emit the payload models. Nothing is registered yet; feature 33 decides the envelope and the events. (spec 0014 AC-20, EVS-1 to EVS-3; `62acb10` (PR 86))
- Cross replica signals in `Orvano.SharedKernel/Signals/`: `SignalKind` (`job`, `cache`, `session`), `ISignalBus`, `ICacheInvalidator`, `ISignalHandler`, `ISignalConnectionObserver`, and `ISignalConnectionState`, implemented in `Orvano.Infrastructure`. A signal enlisted on a platform `DbContext` is sent with `pg_notify` on the `orvano_signal` channel on that transaction's connection just before it commits: one notification per kind, nothing on a rollback, and only the committing attempt's values under the execution strategy. `OrvanoTransactions.InTransactionAsync` runs work in a fresh transaction per attempt. Enlisting with no open transaction, on a context that is not a platform database context, or on one that joined its transaction with `UseTransaction` throws `InvalidOperationException`. Payloads are `{"v":1,"k":"<kind>","d":[…]}`, at most 999 bytes, collapsed to `["*"]` when larger; a malformed payload is logged and ignored. (spec 0013 AC-1 to AC-5; `faf3ad5` (PR 42), `4076b5d` (PR 43), `6c92b1b` (PR 51))
- Cache invalidation across replicas. `HybridCache` is now signal aware with a 60 second default expiry: `ICacheInvalidator.Invalidate` removes the tags on the writer's own instance after the commit, before `CommitAsync` returns, and on every other instance within 5 seconds. Every `serve` process, in any role, runs one listener with a heartbeat. The instance starts disconnected, and while disconnected (a dropped connection, or no heartbeat for `HeartbeatTimeout`) cache reads skip the cache, observers hear `OnDisconnectedAsync` and get a fallback poll, and reconnects back off with full jitter; each connect clears the whole cache before reads use it again. Handlers run on a dispatch loop of their own, each call cut off after `HandlerTimeout`. (spec 0013 AC-6 to AC-10; `4076b5d` (PR 43), `69df8b5` (PR 48), `6c92b1b` (PR 51))
- `ORVANO_SIGNALS__HEARTBEATINTERVAL` (default 30 s), `__HEARTBEATTIMEOUT` (90 s), `__RECONNECTBACKOFFCAP` (30 s), `__FALLBACKPOLLINTERVAL` (5 s), and `__HANDLERTIMEOUT` (10 s). Each must be at least 1 second, the timeout at least twice the interval, and the handler timeout at most the heartbeat timeout, or startup stops naming the setting. The listener logs connects and disconnects and reports the metrics `orvano.infrastructure.signals.connected`, `.sent` (confirmed commits only), and `.received`. (spec 0013 AC-11, AC-13; `4076b5d` (PR 43), `6c92b1b` (PR 51))
- The job queue in `Orvano.SharedKernel/Jobs/`: `IJob`, `IJobHandler<TJob>`, `IJobQueue`, `JobContext`, `EnqueueOptions`, `JobKindOptions`, and `AddJobHandler<TJob, THandler>`. `orvano migrate` creates `jobs.job` and `jobs.schedule`, first in `MigrationOrder`. `EnqueueAsync` inserts the job in the caller's open platform transaction (or in its own) and sends one `job` signal on commit; an optional dedupe key is unique per kind and project. Only `serve` with the `worker` role runs jobs: it claims due jobs with `FOR UPDATE SKIP LOCKED`, renews each lease every third of it, and fences each outcome by attempt. A failed, timed out, or unreadable job retries after a jittered delay up to min(1 hour, 10 s × 2^(attempt − 1)) and ends `dead` with its last error. A job with a project runs as `Caller.System` in that project's scope. Workers wake on the `job` signal, on each signal connect, and on the poll. `CancelProjectJobsAsync` marks a project's jobs `dead`. (spec 0013 AC-14 to AC-23, AC-30; `0e27e1d` (PR 53), `c17cff3` (PR 54), `e6bbe39` (PR 58))
- Recurring jobs with `AddJobSchedule<TJob>`, a five field cron expression parsed by `Cronos`, fired once per occurrence however many workers run. The built in `jobs.cleanup` schedule (daily at 03:17 UTC) deletes succeeded jobs after 7 days and dead jobs after 30. A bad kind or schedule registration stops startup with a message naming it and exit code 1. (spec 0013 AC-24, AC-25; `c17cff3` (PR 54), `51015f2` (PR 56))
- `ORVANO_JOBS__POLLINTERVAL` (default 5 s, 1 s to 5 minutes) and `ORVANO_JOBS__CONCURRENCY` (default the smallest of processor count × 2, 16, and the pool limit; explicit values 1 to 256). The runner reports `orvano.infrastructure.jobs.enqueued`, `.attempts`, `.duration`, `.lag`, `.running`, and `.schedules.fired`, tagged with no ids, and payloads and dedupe keys never appear in logs above Debug. (spec 0013 AC-26, AC-27; `c17cff3` (PR 54))
- The module outbox in `Orvano.SharedKernel/Outbox/`. A module registers versioned event types with `AddOutbox`, maps `<schema>.outbox` with `HasOutbox()`, and publishes with `IOutbox.Publish` in the caller's `SaveChanges` and transaction; a before commit check refuses an event that was never saved. On the `worker` role the dispatcher turns each committed event into one job per subscriber registered with `AddEventHandler<TEvent, THandler>`, so each subscriber retries on its own in the event's project scope. Batches hold 100 events, halved after a failed or cut batch (DSP-5). The built in `outbox.cleanup` schedule (daily at 03:37 UTC) deletes dispatched events after 7 days. The metrics are `orvano.infrastructure.outbox.published`, `.dispatched`, and `.lag`. No module publishes yet. (spec 0013 AC-31 to AC-41; `4fef719` (PR 60), `364f715` (PR 61))

An architecture test allows `AccessContext.Establish` only from the access layer and `JobAccessScope`. (spec 0013 AC-12, AC-28, AC-42; `4076b5d` (PR 43), `6c92b1b` (PR 51), `c17cff3` (PR 54), `364f715` (PR 61), `5b0f633` (PR 64))

- The access control core in `Orvano.SharedKernel/Access/`, the one permissions model databases, storage, realtime, and functions will share.
