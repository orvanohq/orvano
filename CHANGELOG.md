## [Unreleased]

### Added

- The access control core in `Orvano.SharedKernel/Access/`, the one permissions model databases, storage, realtime, and functions will share. A grant is the text token `<action>:<role>`: `read`, `create`, `update`, `delete`, or `execute` for `any`, `guests`, `users`, `user:<uuid>`, or `label:<name>`. `Grant` and `Role` parse it strictly and refuse the reserved `team:`, `member:`, and `verified` forms. `GrantSet.Normalize` turns input into the stored array: `write:<role>` expanded, each action checked against its target (`create` only on tables and buckets, `execute` only on functions), guests and end users limited to their own roles (tokens naming other roles survive their update), deduplicated, sorted, and at most 100. `GrantSet.DefaultsFor` gives an end user `read`, `update`, and `delete` on the rows and files they create; everyone else starts with none. (spec 0012 AC-1, AC-6, AC-7; `b59c56e` (PR 32))
- `Caller`, the one kind every request resolves to (guest, end user, secret key, run key, operator, system), with its role set, and `AccessEvaluator`, the one answer to "may this caller do this?". It allows, filters rows or files by the caller's match tokens when row security is on, answers `404 not_found` for a resource the caller cannot see, and `403 forbidden` for a visible one. Secret keys, run keys, operators, and the system skip grants. `WhereGranted` in `Orvano.SharedKernel/Data/` runs the row filter in the query as a PostgreSQL array overlap (`&&`) with the tokens as one parameter, and a test against a real database proves it returns exactly the allowed rows with correct `limit`, `offset`, `count`, and bulk write counts. End user labels come through `ICallerRolesSource`, which feature 14 implements; the test that a label change reaches every server instance (AC-10) waits for feature 61. (spec 0012 AC-2 to AC-5; `b59c56e` (PR 32))
- The API key scope catalog with a ceiling per key type (`Scopes.Validate` refuses `users.impersonate` and `client.auth.signup` without `client.auth`), the console permission list with `owner` holding all of it, and the endpoint methods `RequireScope`, `RequireClientApi`, and `RequireConsolePermission`. They add endpoint metadata that `UseAccessRequirements()`, placed right after `UseRouting`, enforces: a key without the scope gets `403 insufficient_scope`, a publishable key with that client API off gets `403 forbidden`, and an operator who is not a member, or names a project outside the organization, gets `404 not_found` (a member without the permission gets `403 forbidden`). An endpoint that declares a requirement refuses to run if the middleware is missing. (spec 0012 AC-8, AC-11; `b59c56e` (PR 32), `a38e910` (PR 33))
- `ICallerContext` and `IProjectContext`, registered by `AddAccessContext()` and set only by the access layer (the project only after its check passes), plus the `Error`, `Result<T>`, and `error.ToProblem()` vocabulary for expected failures. `ToProblem` adds `code`, `traceId`, field errors, and the error's extensions. No credential resolver sets the caller yet; features 13 and 14 add them. (spec 0012 PRJ-3, spec 0002 ERR-1 to ERR-4; `b59c56e` (PR 32), `a38e910` (PR 33))
- Architecture tests that fail the build when the access core references an Npgsql, EF Core, or SQL type, when `WhereGranted` leaves the data namespace, when anything outside the access layer implements the caller or project context, when `IProjectContext` gains a public setter, or when `Orvano.SharedKernel` shows its internals to anything but test projects. (spec 0012 AC-9, AC-12; `b59c56e` (PR 32))
- The shared data conventions every platform `DbContext` builds on, in `Orvano.SharedKernel/Data/`. `UseOrvanoConventions(schema, ...)` sets the module's schema, snake case names, the `<schema>.__ef_migrations_history` table, and the default retry, and registers a scoped `TimestampInterceptor` that stamps `CreatedAt` and `UpdatedAt` from the injected `TimeProvider` (and stamps the owner when an owned value changes). `Entity` gives every row an app made uuid v7 `Id`. `HasTextEnum` stores an enum as snake case text guarded by a named CHECK, `HasAnchor` is the only way to point into another module's schema (organization, project, operator, end user, each with its allowed delete rules), `[DataClass]` marks each stored text or bytes property as secret, personal, or public, and `EncryptedValue` holds ciphertext that never prints or serializes its bytes. `EmailAddress.Normalize` and the `ISecretProtector` interface come with it. No production table exists yet; features 13 onward create them from the spec's catalog. (spec 0011 AC-1 to AC-5, AC-9, AC-11; `f100b4c` (PR 30))
- Architecture tests that walk every server `DbContext` model and fail the build on a context that skips `UseOrvanoConventions` or maps a table outside its schema, a cross schema FK to anything but the four anchors (or with a delete rule REF-3 forbids), a text, bytes, address, JSON, or `EncryptedValue` property without `[DataClass]`, a store generated key, two contexts sharing a schema, and a module context missing from `MigrationOrder`. Each rule is proven by a deliberately broken sample context. (spec 0011 AC-3, AC-6 to AC-8; `f100b4c` (PR 30))
- The platform data model catalog: every table later features build, with its owning module, columns, anchors, delete rules, data classes, and retention, plus a traceability table from scope features 12 to 60 to their tables. (spec 0011 CAT-1, CAT-2, AC-10; `f100b4c` (PR 30))
- Community files at the repo root: `SECURITY.md` (private vulnerability reporting, supported versions, response targets, scope, and safe harbor), `CODE_OF_CONDUCT.md` (Contributor Covenant 3.0), `CONTRIBUTING.md` (setup pointers, branches and PRs, the DCO sign off and how to fix a failed check, AI tools, Windows notes), `SUPPORT.md`, and `TRADEMARKS.md`. `README.md` links them from a new Community section. The project security address is still a placeholder, to be filled in before the repo goes public. (spec 0010 VRP, COC, COM; `65f6379` (old PR 4))
- Issue forms for bug reports and feature requests, with blank issues turned off and links to Discussions Q&A and private reporting, plus `.github/CODEOWNERS`. (spec 0010 ISS; `65f6379` (old PR 4))
- A `dco` sign off job inside `ci-gate` that runs on every PR. It lists each commit whose sign off is missing or doesn't match its author, and prints the `git rebase --signoff` fix. Merge commits are skipped. (spec 0010 AC-7, spec 0009 CTB-3; `65f6379` (old PR 4))
- `tooling/scripts/github-settings.mjs`, which keeps the GitHub repo and org settings (the `main` ruleset, security features, labels, Discussions categories) as code. Check mode is read only and exits 1 on drift; `--apply` writes the differences with your own `gh` login. It never runs in CI. (spec 0010 SET, RUL, ORG; `65f6379` (old PR 4))
- `tooling/scripts/export-template.mjs`, which writes a template repo's tree from `tooling/starters/**` into a clone, with `--check` to report drift. The starters gain CodeQL and dependency review workflows (the Dart export has no CodeQL) and a new `tooling/starters/org/` source for the org `.github` repo. The template repos and the org `.github` repo themselves don't exist yet. (spec 0010 TPL; `65f6379` (old PR 4))
- `node --test` suites for the dco job and both scripts, run by `pnpm test:tooling`. (spec 0010 AC-19; `65f6379` (old PR 4), `8204a94` (old PR 5))

### Changed

- Specs 0002, 0006, 0007, and 0011 now point to spec 0012. The catalog gains `databases.table` and the grant columns on buckets, files, and functions, `api_key.scopes` takes spec 0012's scope lists with a CHECK per key type, and `audit_event.actor_kind` gains `function`. End user labels and resource grants count as security related cache entries (60 second cap), and the feature 9 follow ups in specs 0006 and 0011 are closed. (spec 0012 AC-8, AC-9; `b59c56e` (PR 32))
- `Orvano.SharedKernel` now references `EFCore.NamingConventions` and the Npgsql EF Core provider, and spec 0002 LAY-3 allows the naming package. `PostgresFixture` gains `ConnectionString(database)` and `CreateDatabaseAsync(prefix)`, so a test class can get its own database on the one shared container. (spec 0011 build plan step 1, spec 0002 TST-5; `f100b4c` (PR 30))
- CodeQL now uploads its results on every event, fork and Dependabot PRs included, so the code scanning gate can be added once both uploads are proven. (spec 0010 RUL-5; `65f6379` (old PR 4))
- The `dco` job skips a commit authored by a bot only when a bot also opened the PR. In a PR opened by a person, a bot authored commit is checked like any other and fails without a matching sign off, with the `git commit --amend --reset-author -s` fix. If the PR author type is missing, it counts as a person. This closes a gap where anyone could claim the skip through a git author email. (spec 0010 DCO-2; `19f6a6d` (old PR 6), `eda5a0a` (old PR 7))

### Fixed

- A caller refused by `RequireScope`, `RequireClientApi`, or `RequireConsolePermission` now gets its `403` or `404` before the request body is bound and validated. Before, the checks ran as endpoint filters, so a refused caller who sent a bad body got a `400` that named the fields. (spec 0012 DEN-5; `a38e910` (PR 33))
- A rate limited `Error` now answers its `429` with a `Retry-After` header taken from `retryAfterSeconds`. Before, the header was missing. (spec 0002 ERR-4; `a38e910` (PR 33))
- `export-template.mjs` refuses to write into the core repo (including a symlink, a folder inside or above it, or a worktree of it), and refuses a clone with uncommitted changes to tracked files unless you pass `--force`. Before, a wrong target could delete tracked files. (`8204a94` (old PR 5))
- `export-template.mjs` no longer crashes on a second run before you commit a removal, `--check` no longer calls an already removed file stale, and the `.github` target no longer needs the core's `origin/main`. (`8204a94` (old PR 5))
- `github-settings.mjs` exits 2 on a GraphQL error or an unexpected API response, so exit 1 always means drift. (`8204a94` (old PR 5))
- `CONTRIBUTING.md` (core and org) points newcomers to open issues without the `triage` label. (`8204a94` (old PR 5))
