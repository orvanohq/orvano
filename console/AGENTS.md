# Console

## Overview

The Orvano console: a React SPA built with Vite and served as static files by Caddy in production (no Node server). It manages every project on an install. Styling, components, and the shell come with scope row 5 (design system and console shell).

## Stack

- React 19, TypeScript 6, Vite 8
- TanStack Router (file routes, auto code splitting) and TanStack Query
- Platform calls through the private generated `@orvano/console-client` (spec 0001, `console` audience), once it exists

## Key files

| File | Owns |
|---|---|
| `src/main.tsx` | Query client, router, and app root |
| `src/routes/` | File routes; `__root.tsx` carries the router context (`queryClient`) |
| `src/routeTree.gen.ts` | Generated by the router plugin; never edit by hand |
| `vite.config.ts` | Dev proxy for `/v1` and `/v1/realtime` to the Aspire started roles |

## Commands

```bash
# Dev server alone (normally the AppHost starts it)
pnpm --filter @orvano/console dev

# Build (typecheck + bundle)
pnpm --filter @orvano/console build
```

## Conventions

- Feature code sits beside the route that uses it; move it to a shared folder only once two routes need it.
- Server data goes through TanStack Query, never ad hoc `fetch` in components. Call the API only through `@orvano/console-client`, never with handwritten URLs.
- Named exports only. Route files keep the `Route` export TanStack Router requires.
- Components are PascalCase; other files are kebab-case.
- WCAG AA: every control reachable by keyboard with visible focus, labelled inputs, AA contrast.
- Tests: Vitest plus Testing Library, set up when row 5 brings real screens.

## Gotchas

- The console is always same origin as the API (Vite proxy in dev, Caddy in production), so there is no CORS. Routing bugs that differ between the two only show up in the compose check.
