# Console

## Overview

The Orvano console: a React SPA built with Vite and served as static files by Caddy in production (no Node server). It manages every project on an install. The design system (Tailwind v4 tokens, shadcn components on Base UI) and the org and project shell are in place (scope row 5, spec 0005).

## Stack

- React 19, TypeScript 6, Vite 8
- TanStack Router (file routes, auto code splitting) and TanStack Query
- Tailwind CSS v4 with CSS variable tokens, shadcn/ui components (Base UI flavor), Lucide icons, TanStack Form with Zod, TanStack Table
- Platform calls through the private generated `@orvano/console-client` (spec 0001, `console` audience)

## Key files

| File | Owns |
|---|---|
| `src/main.tsx` | Query client, router, and app root |
| `src/routes/` | File routes; `__root.tsx` carries the router context (`queryClient`) |
| `src/routeTree.gen.ts` | Generated by the router plugin; never edit by hand |
| `vite.config.ts` | Dev proxy for `/v1` and `/v1/realtime` to the Aspire started roles; with `CONSOLE_DEV_SESSION` set it adds the fixture console cookie to `/v1/console` calls |
| `design.md` | The design system: tokens, type, density, and the component inventory |
| `src/styles/tokens.css` | Every design token; the only file allowed a color literal (a unit test scans for them) |
| `src/components/ui/` | shadcn components (Base UI flavor) restyled to the tokens; `keyboard-scripts.ts` is each component's keyboard test as data |
| `src/shell/` | Top bar, org and project switchers, sidebar, status and error panels; `nav.ts` is the only place sidebar entries are declared; `page-heading.tsx` renders every page's `h1` |
| `src/lib/` | `console-client.ts` (the one client, plus `projectClient(id)`), `session.ts` (`redirectToSignIn`), preferences, roles, toast helpers |
| `src/dev/` | The `/dev/components` catalog; dev only, never in the production build |
| `public/theme-init.js` | Sets `data-theme` and `data-density` before first paint; a classic script so the CSP needs no hash |
| `e2e/` | Playwright tests against the gateway on `:8081` |

## Commands

```bash
# Dev server alone (normally the AppHost starts it)
pnpm --filter @orvano/console dev

# Build (typecheck + bundle)
pnpm --filter @orvano/console build

# Unit tests (node) and browser tests (real Chromium with axe); `test:unit` runs the node project only
pnpm --filter @orvano/console exec playwright install chromium   # once
pnpm --filter @orvano/console test

# End to end: start the gateway and a real API on :8081 first (`CONSOLE_URL` overrides it)
docker compose -f tests/scenarios/compose.yml --profile console up -d --build --wait
pnpm --filter @orvano/console test:e2e

# Dev signed in to the Fixtures org (api and worker run in Test)
dotnet run --project dev/Orvano.AppHost -- --OrvanoDev:Fixtures=true
```

## Conventions

- Feature code sits beside the route that uses it; move it to a shared folder only once two routes need it.
- Server data goes through TanStack Query, never ad hoc `fetch` in components. Call the API only through `@orvano/console-client`, never with handwritten URLs.
- Named exports only. Route files keep the `Route` export TanStack Router requires.
- Components are PascalCase; other files are kebab-case.
- WCAG AA: every control reachable by keyboard with visible focus, labelled inputs, AA contrast.
- Design system: build all UI to [design.md](design.md); token values live in `src/styles/tokens.css`, and components use only tokens.
- Tests: `*.unit.test.ts` (Vitest, node) and `*.browser.test.tsx` (Vitest browser mode in real Chromium with axe) sit beside the code; `e2e/` holds the Playwright tests. A new component or variant needs a catalog example in `src/dev/examples.tsx` and an entry in `keyboard-scripts.ts`.

## Gotchas

- The console is always same origin as the API (Vite proxy in dev, Caddy in production), so there is no CORS. Routing bugs that differ between the two only show up in the compose check.
- The production CSP allows scripts and styles only from the console's own files: no inline script, and no library that injects a `<style>` element (why the toast is Base UI's, not sonner). An exception is a hash plus a note in `design.md`.
- `/dev/components` exists only in dev, and the production build must not contain the string `orvano-dev-catalog` (an e2e test checks it), so never import `src/dev/` statically.
- `CONSOLE_DEV_SESSION` is read by the Vite dev server only (never an `ORVANO_*` setting). The AppHost sets it with `--OrvanoDev:Fixtures=true`, and row 8 removes both.
