## Minor

### 🟡 The interceptor runs change detection two extra times and copies every entry on every save, `server/src/Orvano.SharedKernel/Data/TimestampInterceptor.cs:40-41` and `:73`

**Problem**: `Stamp` calls `OwnersOfChangedOwnedEntities`, which calls `context.ChangeTracker.Entries()` and copies the result into a list, even when the model has no owned types. Then `Stamp` calls `Entries<ITimestamped>()` again. Each of those calls runs `DetectChanges` first (when automatic detection is on) and builds an `EntityEntry` wrapper for every tracked entity. So every save does three change detection passes and about two extra allocations per tracked entity.
**Why it matters**: A bulk save of thousands of entities (imports, usage rollups) pays this on the hot path of every write in every module. It is linear, not quadratic, so it will not break anything, but it is pure overhead and easy to avoid.
**Suggested fix**: Call `ChangeTracker.Entries()` once, filter that single list for `ITimestamped` and for changed owned entries, and skip the owner walk when the model has no owned entity type (check once per context type, or look at the one list). Keep the tests; they already cover the behavior.
**Status**: Fixed. `Stamp` calls `ChangeTracker.Entries()` once and walks that one list for both the `ITimestamped` entries and the changed owned entries, so a save runs change detection once in the interceptor and builds one entry wrapper per tracked entity. The owner walk still returns early when no owned entry changed. The existing stamping tests (sync, async, auto detect off, four owned paths) pass unchanged.

### 🟡 The `Setup` rule does not check that every table sits in the module schema, `server/tests/Orvano.ArchitectureTests/Data/DataModelRules.cs:65-99` and `:204-208`

**Problem**: `Setup` checks only the model's default schema, and `SharedSchemas` compares only default schemas. An entity mapped with `ToTable("x", "public")` or into another module's schema passes AC-6 (when it has no FK), AC-7, AC-8 and `Setup`. MOD-1 says one schema per module and MOD-3 says a module writes only its own schema.
**Why it matters**: The point of this feature is that a later module cannot slip out of its schema. A single `ToTable(..., "other")` would put a table into someone else's schema and the migrations history would not know it.
**Suggested fix**: In `Setup` (or a new rule), fail any module entity type that has a table and whose `GetSchema() ?? default` differs from the default schema, except the anchor stubs. Add a bad sample for it. If this was left out on purpose, say so in AC-8.
**Status**: Fixed. `Setup` now fails any module entity type with a table whose schema is not the module schema (anchor stubs excepted; `Marks` checks them), naming MOD-1 and MOD-3. New bad sample `ForeignTableContext` (`ToTable("composite", "public")`) and test `Setup_fails_when_a_table_is_mapped_outside_the_module_schema`. Spec 0011 AC-3 and the guard test line say it.

### 🟡 The data class rule cannot see several string like types, `server/tests/Orvano.ArchitectureTests/Data/DataModelRules.cs:23-24`

**Problem**: `ClassifiedTypes` is exactly the spec list. Npgsql and EF 10 also store `List<string>` and `IReadOnlyList<string>` (primitive collections, text[] or json), `JsonElement`, `Dictionary<string, string>`, `PhysicalAddress`, `IPNetwork` and `ReadOnlyMemory<byte>` as plain columns. A property of one of those types needs no `[DataClass]` and the test stays green.
**Why it matters**: Feature 49 (finding a user's personal data) and the LOG-3 redaction list rely on every text bearing column being marked. A `List<string> Emails` is a realistic way to escape. Also a wrapper type with a string converter (for example a future `Email` value object) escapes, since only `ClrType` is read.
**Suggested fix**: Widen the rule to also check properties whose provider type (the type after the value converter) is in the list, plus element types of primitive collections, and add the other types above. Update AC-7 to match. Add a sample for `List<string>`.
**Status**: Fixed. The list adds `ReadOnlyMemory<byte>`, `Memory<byte>`, `IPNetwork`, `PhysicalAddress`, `NpgsqlInet`, and `JsonElement` (`NpgsqlCidr` is obsolete, `IPNetwork` replaces it). A type also counts when it is an array, collection, or dictionary of a listed type (`List<string>`, `Dictionary<string, string>`), or when its value converter stores a listed type (`Uri`, a wrapper stored as text); enums are left out, since `HasTextEnum` stores a closed list of names. `Unmarked` gains `List<string> Emails` and `Uri? Website`, and the test expects both. Spec 0011 AC-7 lists the types. Shadow and field only properties still cannot carry the attribute and are not checked, as before.

### 🟡 `HasTextEnum` edge cases are guarded by a throw that may be wrong, and one is untested, `server/src/Orvano.SharedKernel/Data/OrvanoConventionSetPlugin.cs:89-102`

**Problem**: (1) `table is null` throws "not mapped to a table". An abstract base type in a table per concrete type (TPC) mapping has no table of its own, so a `HasTextEnum` property declared on the abstract base would throw although each concrete table does have the column and needs its CHECK. I reasoned this from EF's mapping rules and did not run it. (2) `HasTextEnum` on an owned type that shares its owner's table (table splitting) takes its column name from the owner prefix (`label_kind`); no test proves the CHECK uses that final column name and the name `ck_<table>_<column>`.
**Why it matters**: Both are plausible in later modules. The first is a loud failure (fixable), the second would be a wrong or missing CHECK if the column name were read too early. Low odds, but this is the same failure class the earlier reviews cared about.
**Suggested fix**: Add one sample with an owned type in the owner's table and a `HasTextEnum` property, and assert the CHECK text. For TPC, either document in the throw message that the mark goes on the concrete types, or create the CHECK per mapped table.
**Status**: Fixed, both parts. The plugin now adds the CHECK per mapped table: each entity type with a table checks its own properties plus those of base types that have no table there (TPC), reads the column with `GetColumnName(StoreObjectIdentifier)`, and removes the marks only after every type is done; a mark no table took still throws. New tests: `Text_enum_on_a_TPC_base_gets_a_check_on_each_concrete_table_when_built` (`ck_circle_kind`, `ck_square_kind`, none on the abstract base; the old code threw) and `Text_enum_in_an_owned_type_gets_its_check_on_the_owner_table_with_the_prefixed_column_when_built` (`ck_badge_style_kind` on `"style_kind"`). Spec 0011 AC-4 and the `HasTextEnum` API row say it.

## Nits

- ⚪ `server/src/Orvano.SharedKernel/Data/Entity.cs:9`, the initializer `Guid.CreateVersion7()` also runs for every entity EF materializes from a query, and EF then overwrites it. It costs a clock read and random bytes per row read. Fine today; keep in mind for large reads (a private constructor EF uses is not possible with the spec's simple `Entity`, so this is a note, not a request). **Skipped**: avoiding it means a constructor EF binds on every entity type in every module, against the spec's one line `Entity`. The cost is one clock read and 10 random bytes per row materialized, small next to reading the row from PostgreSQL. Revisit only if a profile of a large read shows it.
- ⚪ `server/src/Orvano.SharedKernel/Data/EncryptedValue.cs:43-45`, a non nullable `EncryptedValue` left at `default` is stored as an empty `bytea`, not NULL and not an error. An empty envelope can never decrypt. Consider throwing in the converter on empty bytes so a forgotten secret fails at save. **Fixed**: `EncryptedValue.Converter` throws `InvalidOperationException` on an empty envelope when storing; test `Storing_throws_when_the_envelope_is_empty`; spec 0011 ENC-1 and the API table say it.
- ⚪ `server/src/Orvano.SharedKernel/Data/Anchor.cs:96-115`, the stubs are internal nested classes, so every module's model snapshot names `Orvano.SharedKernel.Data.Anchors+ProjectAnchor` and friends. Renaming or moving them later changes all snapshots. Worth a comment saying the names are frozen. **Fixed**: the comment above the stubs in `Anchor.cs` says every snapshot names them, so their names and nesting are frozen.
- ⚪ `server/tests/Orvano.ArchitectureTests/Data/SampleContexts.cs:15-18`, the static `ServiceProvider` and its `NpgsqlDataSource` are never disposed. Harmless in a test process. **Skipped**: the data source never opens a connection (`Database=unused`), and disposing it would need an assembly fixture only to free memory at process exit.
- ⚪ `docs/scope/foundations.md:116`, still says an architecture test covers the AC-10 traceability check; it is a hand check in `verify.md:40`. Reword to "(AC-10 is checked by hand in verify.md)" through `/scope` or `/sync`. **Fixed**: `foundations.md` now reads "keys, schemas (AC-6 to AC-8) (AC-10 is checked by hand in verify.md)".
- ⚪ `docs/specs/0002-dotnet-backend-practices/index.md:117`, LAY-3 says "and nothing else" while SharedKernel now references `EFCore.NamingConventions` (spec 0011 step 1). Fix it in `/architect` before anyone writes an architecture test for allowed packages, because that test would fail on the current code. (The same spec's DAT-2 at line 136 already names the package.) **Fixed**: LAY-3 now allows `EFCore.NamingConventions` (DAT-2, spec 0011) next to EF Core relational and Npgsql.
- ⚪ `server/src/Orvano.SharedKernel/Data/OrvanoConventionSetPlugin.cs:114-115`, the CHECK list and column name are put into SQL text without escaping a quote. Enum member names and column names cannot contain a quote, so there is no injection path today; a one line comment would say why it is safe. **Fixed**: the plugin escapes both (`'` doubled in values, `"` doubled in the column name) with a comment saying why, so a later naming change cannot break out of the literal. Output is unchanged for today's names.

## Strengths

- Every earlier fix comes with a test that fails on the old behavior (unmarked owned and nested complex strings, auto detect off, owned added and removed, base64 JSON, moved history table). The architecture tests use deliberately bad contexts, so each rule is shown to catch its own slip.
- The `Setup` rule plus `SchemaOf` and the `MigrationOrder` equality test mean the first real module context turns every rule on without anyone having to remember. That was the biggest risk in the first review and it is closed in the right place (a test, not a note).
- The convention plugin design is careful about EF internals: constant extension hash with per context reads, a model cache key that includes the schema, an interceptor ordered ahead of `AddInterceptors`, retry first and history table last. The live tests cover xmin concurrency, the CHECK by constraint name, `NULLS NOT DISTINCT`, delete rules for all four anchors, and a real two module `MigrateAsync`.
- Spec 0011 now describes the code as built (AC-2 to AC-8, API table), which is what keeps the next module author from guessing.
- The dependency is clean: `EFCore.NamingConventions` 10.0.1 is referenced only by `Orvano.SharedKernel`, the lock file resolves the same version, and `SharedKernel` references no other Orvano project (`ProjectReferenceTests.cs:41-42`).
