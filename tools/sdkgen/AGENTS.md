# SdkGen

## Overview

Orvano's own generator (spec 0001), a C# console app. It reads `contract/dist/openapi.json`, validates it, and writes the generated layer of every SDK, the server's `Orvano.Contract` types, and the scenario dispatch tables. Two runs in a row must produce no diff; CI checks both.

## Pipeline and key files

| Stage | File |
|---|---|
| Parse with Microsoft.OpenApi 2.x, build the model, validate (AC-2) | `Contract/ContractReader.cs`, `Contract/ContractModel.cs` |
| Map types and names per language into view models | `Languages/TypeScript.cs`, `Languages/Dart.cs`, `Languages/CSharp.cs` |
| Render Scriban templates | `Rendering/TemplateRenderer.cs`, `templates/<ts\|dart\|csharp>/*.scriban` |
| Docs snippets, one per public operation per SDK, into `contract/dist/examples/<sdk>/` (AC-15) | `Languages/Snippets.cs`, `templates/snippets/*.scriban` |
| `contract/dist/openapi.public.json`: the contract minus console and test operations and the schemas only they reach | `Contract/PublicContract.cs` |
| Write, delete stale files, format | `Rendering/OutputWriter.cs` |
| Stamp `VERSION` into package.json and pubspec files, and a section into each Dart CHANGELOG (AC-11) | `Rendering/ManifestStamper.cs` |
| Entry, repo root discovery, exit codes | `Program.cs` |

## Commands

```bash
dotnet run --project tools/sdkgen        # from anywhere in the repo; needs pnpm install and flutter pub get first
dotnet test --project tools/tests/Orvano.SdkGen.Tests   # unit tests; no formatters or Docker needed
```

Exit code 1 with one `error:` line per contract problem, and nothing written. Exit 0 after writing and formatting.

## Conventions

- Type and name mapping lives in C# (`Type`, `FromJson`, `ToJson` in each language file). Templates stay dumb; view model members appear in snake_case (`ClassName` becomes `class_name`).
- Each output folder is owned whole: a file the run did not write is deleted. The exception is `OwnsDirectory: false` (the public contract beside the hand built `openapi.json`), which writes only its own files. Output is sorted with ordinal comparison, so reruns are byte identical.
- Formatting runs after rendering: `pnpm exec prettier`, `dart format`, `dotnet format whitespace --folder`. A missing tool is an error, never a skip.
- A new contract feature (for example discriminated unions) means: accept it in `ContractReader`, map it in all three language files, and render it in all three template folders.
- Every generated file starts with `Generated by Orvano SdkGen. Do not edit.`
- Output routing: public operations go by audience into the SDK packages; `console` ones only into `sdks/console-client/`; anything marked `x-orvano-test` (operations, models, events, error codes) only into `tests/scenarios/runners/*/generated/` as test services on the matching SDK client, plus `Orvano.Contract`. Published output never contains `/v1/test/`, and CI greps `sdks/` and `contract/dist/examples/` for it.

## Gotchas

- `dart format` style depends on the Dart language version the pub workspace resolves, so run `flutter pub get` first, as CI does.
- Generated C# must pass the analyzers: add `using` lines only when used (IDE0005 is a warning), give every public member a doc (CS1591; the generator falls back to a stock sentence), and never use an `<auto-generated>` header, which would switch nullable checks off.
- Generated TS is linted with type aware ESLint like handwritten code.
- TypeSpec's OpenAPI 3.1 emitter writes `Record<T>` as `unevaluatedProperties`, not `additionalProperties`; `ContractReader.MapValues` reads both.
- In Dart `toJson`, an optional value that needs no conversion is written `'x': ?x`; the `if (x case final v?)` form fails `--fatal-infos` (`use_null_aware_elements`) there.
- Tests in `tools/tests/Orvano.SdkGen.Tests` call each stage directly: reader tests change one thing in the committed `openapi.json`, and snippet and mapping tests build small contracts and render the real templates.
- Snippet values come from each property's `@example`, else a placeholder by type. TypeSpec does not emit `@example` on parameters, so path and query values are always placeholders.
- Lint traps already hit: TS rejects `void` as a type argument (a no content call uses `request<undefined>`), and a cast inside a registry typed as `unknown` needs an explicit return type. Dart runs `--fatal-infos`, so a nullable value in `toJson` uses a `switch` expression, not `x == null ? null : x!...`.
