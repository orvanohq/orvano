Sign in with Microsoft works like [Sign in with Google](/docs/auth/sign-in-with-google/), by redirect, for personal Microsoft accounts and for work and school accounts (Microsoft Entra ID).

## 1. Register the app

1. In the Microsoft Entra admin center, open **App registrations** and select **New registration**.
2. Choose who may sign in. This matches the **Tenant** field in Orvano:

   | Supported account types | Tenant in Orvano |
   |---|---|
   | Any organization and personal accounts | `common` (the default) |
   | Any organization only | `organizations` |
   | Personal accounts only | `consumers` |
   | This organization only | your tenant ID |

3. Under **Redirect URI**, choose **Web** and paste the **Callback URL** from the Microsoft dialog on the **Sign in methods** page.
4. Under **Certificates and secrets**, create a client secret.
5. Under **Token configuration**, select **Add optional claim**, choose **ID**, and add `email` and `xms_edov`.
6. Copy the **Application (client) ID** and the secret into the Microsoft dialog, set the tenant, turn on **Enabled**, and select **Save**.

### Why `xms_edov` matters

Microsoft lets an organization put any email on an account, verified or not. The `xms_edov` claim says whether Microsoft verified the email's domain. Orvano counts a Microsoft email as verified only when `xms_edov` is true. Without it, Microsoft users get no email in Orvano, and they never sign in to an existing account by email.

Even with `xms_edov` set, a personal Microsoft account whose sign in name is an address at another provider (`someone@gmail.com`, say) gets no email in Orvano: Microsoft doesn't own that domain, so `xms_edov` is never true for it. The user still signs in; the address stays on their Microsoft [identity](/docs/auth/link-identities/), marked unverified.
