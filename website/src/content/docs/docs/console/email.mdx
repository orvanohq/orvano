A project's **Email** page has three tabs: **Settings** (the email server it sends through), **Templates** (what its emails say), and **Log** (what it sent). Every member can see them; owners and developers can change them.

## Settings

By default a project sends through the install's email server, and the page says **Using this server's email settings**. On a [local install](/docs/local/) that server is the local inbox, so emails show up at `http://localhost:8025`.

<Screenshot name="email-settings" alt="The Email page's Settings tab, saying the project uses this server's email settings, above an empty SMTP server form." />

To send from your own domain, fill in the **SMTP server** form: **Host**, **Port**, **Security**, **Username**, **Password**, **From email**, and optionally **From name** and **Reply to**. Select **Send test email** to send a test to your own address with the values in the form, then save. **Stop using these settings** goes back to the install's server.

A project's server must be on a public address ([`smtp_host_not_allowed`](/errors/smtp_host_not_allowed/) otherwise). [Email delivery](/docs/self-hosting/email-delivery/) covers providers, the install's server, and what each failure means.

## Templates

Orvano sends five emails, each from a template you can rewrite in your product's own words:

<Screenshot name="email-templates" alt="The Templates tab listing Email verification, Password reset, Magic link, and Email code, each marked Default." />

| Template | Sent for |
|---|---|
| Email verification | [email verification](/docs/auth/email-verification/), and confirming an [email change](/docs/auth/change-email/) |
| Password reset | [password reset](/docs/auth/password-reset/) |
| Magic link | [magic links](/docs/auth/magic-links/) |
| Email code | [email codes](/docs/auth/email-codes/) |
| Security alert | a change to a user's sign in security: [MFA](/docs/auth/mfa/) turned on or off, a [passkey](/docs/auth/passkeys/) added or removed, recovery codes made or used; or a sign up with their email while the project [requires a verified email](/docs/auth/email-verification/#require-a-verified-email) |

Open one to edit its **Subject**, **HTML**, and **Text**. The preview on the right updates as you type, with your project's name and your own email as sample values. **Send test** emails the preview to you, and **Reset to default** brings back Orvano's version. Leave **Text** empty to generate it from the HTML.

<Screenshot name="email-template-editor" alt="The Email verification template editor: the subject and HTML on the left, and a preview of the email with a Verify email button on the right." />

Templates use [Liquid](https://shopify.github.io/liquid/). Each template offers these variables, with a copy button for each in the editor:

| Variable | What it holds |
|---|---|
| `project.name` | Your project's name. |
| `user.email` | The address the email is sent to (not in Security alert). |
| `user.name` | The user's name; empty when they haven't set one (not in Security alert). |
| `action_url` | The link the user opens to finish (Email verification, Password reset, and Magic link). |
| `code` | The 6 digit code (Email code only). |
| `expires_in_minutes` | How many minutes the link or code works (not in Security alert). |
| `reject_url` | The second link of a verification email, which says the sign up wasn't the inbox owner's (Email verification only; empty in an email change email, so wrap it in `{% if reject_url %}`). |
| `alert` | What changed, for Security alert only: `mfa_enabled`, `mfa_disabled`, `passkey_added`, `passkey_removed`, `recovery_codes_created`, `recovery_code_used`, or `sign_up_attempt` (someone signed up again with the user's email). Word each with a Liquid `case`. |
| `occurred_at` | When it changed, in UTC, such as `2026-06-01 10:00 UTC` (Security alert only). |

A template that uses any other variable can't be saved ([`template_invalid`](/errors/template_invalid/)). Values are HTML encoded in the HTML part, and `include` and `render` aren't allowed. If a saved template ever fails when an email is sent, Orvano sends the default instead, so the user still gets their link.

## Log

The **Log** tab lists the project's emails from the last 30 days: the template, the masked recipient, whether it was sent, how many tries it took, and the reason for any failure. Orvano keeps no email content once an email is sent.
