You build an ASP.NET Core Minimal API whose `GET /me` reads a user's access token, checks it with the `Orvano` NuGet package {version}, and answers with that user. You also write a command that creates a user with a server API key. This is the pattern for any backend of yours that sits next to an app signing users in with Orvano. It takes about ten minutes.

The finished app is [`examples/dotnet-quickstart`](https://github.com/orvanohq/orvano/tree/main/examples/dotnet-quickstart) in the Orvano repo. Every file below comes from it, and CI runs it on every change.

On a server, you create users with the API key, for example when you import them from another system. `dotnet run -- create-user` creates one and exits before the web server starts; it runs on your machine and is never an open HTTP route:

```sh

```

You should see `Created user` with the new user's ID. The user is in the console too, on your project's **Users** page.

## 7. Check a user's token on your server

`GET /me` reads the token from `Authorization: Bearer <token>`. `VerifyAccessTokenAsync` checks its signature, its project, and its expiry, and answers with the user's ID, so the server loads the user with `Users.GetAsync`. A missing or bad token gets 401.

## 8. Try it

Start the server with `dotnet run`. You should see `Now listening on: http://localhost:3002`.

In another terminal (with the same settings), sign in as the user you created to get an access token, the way an app's sign in would, and call `/me` with it:

  <TabItem label="macOS and Linux">

  </TabItem>
  <TabItem label="Windows PowerShell">
    <Code code={token.powershell} lang="powershell" />
  </TabItem>
</Tabs>

<Steps>

1. You should see `200 OK` and the user's ID, email, and name.
2. Call `/me` again without the `Authorization` header. You should see `401 Unauthorized`.
3. Change one character of the token and call it again. You should see `401` again: the signature no longer matches.

</Steps>

Access tokens last 15 minutes. In a real app, the client SDK refreshes the session and sends a fresh token with each call.
