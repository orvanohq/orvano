`orvano_flutter` is the client SDK for Flutter apps on web, iOS, and Android (Flutter 3.32 or later). It signs users in, acts as them, and keeps their session in the platform's secure storage. It has no API key and can't manage other users; that's what the [Dart server SDK](/docs/sdks/dart/) is for.

## Install

<Code code={`flutter pub add orvano_flutter:${version}`} lang="sh" />

The [Flutter quickstart](/docs/quickstarts/flutter/) builds a full app with it, including what each platform needs to reach a local Orvano.

## Create the client

```dart
import 'package:flutter/widgets.dart';
import 'package:orvano_flutter/orvano_flutter.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  final orvano = Orvano(
    createClient(endpoint: 'http://localhost:7700', project: 'your-project-id'),
  );
  // pass orvano to your app
}
```

Make one client for the whole app, after `WidgetsFlutterBinding.ensureInitialized()`. `createClient` takes:

| Option | What it does |
|---|---|
| `endpoint` | Your Orvano server, without `/v1`. Required. |
| `project` | Your project ID. Required. |
| `storage` | The `FlutterSecureStorage` to keep the session in, for your own platform options. |
| `session` | Your own `SessionStore` instead of secure storage. |
| `timeout`, `maxRetries` | 30 seconds and 3 retries (of reads after a 429 or 503) by default. |
| `httpClient`, `headers`, `onWarning` | Your own `http.Client`, extra headers, and where warnings go. |
| `passkeys` | The authenticator for [passkeys](#passkeys), `PlatformPasskeys()` from `orvano_flutter_passkeys`. None by default. |

Register your app as a [platform](/docs/concepts/platforms/) of the project: its hostname for web, its bundle ID for iOS, its package name for Android.

## Sessions

Signing in stores the session in secure storage (Keychain on iOS, Keystore on Android, encrypted storage on web) under `orvano.session.<projectId>`. Before each call the client refreshes the session when its access token has less than a minute left, and it checks the session again when the app comes back to the front.

```dart
final session = await orvano.client.getSession(); // null when signed out

orvano.client.authStateChanges.listen((change) {
  // change.event is signedIn, signedOut, tokenRefreshed, userUpdated, or mfaRequired
});
```

A session the server has ended (a password change elsewhere, or blocking the user) reads as `signedOut` on the next refresh.

## What it can call

| Service | Methods |
|---|---|
| `account` | `create`, `createPasswordSession`, `get`, `update`, `updatePassword`, `delete`, `deleteCurrentSession` (sign out), `listSessions`, `listSessionsAll`, `deleteSession`, `deleteOtherSessions`, `refreshSession`, and the email flows: `createVerification`, `verifyEmail`, `createRecovery`, `completeRecovery`, `createMagicLink`, `createMagicLinkSession`, `createEmailCode`, `createEmailCodeSession`, `updateEmail`, `confirmEmailChange`, `rejectEmailVerification`, guests: `createAnonymousSession`, `upgradeAnonymous`, MFA: `getMfa`, `createTotp`, `confirmTotp`, `deleteTotp`, `createRecoveryCodes`, `verifyMfa`, `createMfaSession`, the required MFA enrollment: `createMfaEnrollmentTotp`, `completeMfaEnrollmentTotp`, `createMfaEnrollmentPasskey`, `completeMfaEnrollmentPasskey`, and passkeys: `listPasskeys`, `updatePasskey`, `deletePasskey`, and the ceremony operations the helpers below call |
| `health` | `get` |
| `keys` | `getJwks`, `getOpenIdConfiguration` |

Requests take a model, for example `orvano.account.createPasswordSession(CreatePasswordSessionRequest(email: email, password: password))`.

## Emailed links

When your app opens from an emailed link, pass the link to `orvano.client.handleLink(uri)`. It reads the link's type and finishes it: it verifies the email, confirms an email change, signs the user in from a magic link, or takes back an account someone else signed up with (`verification_reject`). A password reset link needs the new password: `handleLink(uri, password: newPassword)`. It answers `null` for a link that isn't from Orvano.

The SDK doesn't open links for you. Use a package such as `app_links` to receive them. Magic links and password reset links must be https links, so they need Android App Links and iOS Universal Links on a real domain; [Email verification](/docs/auth/email-verification/#flutter-deep-links) explains the setup. During development, sign in with an [emailed code](/docs/auth/email-codes/) instead: it needs no links.

## MFA

A sign in for a user with [MFA](/docs/auth/mfa/) on emits `mfaRequired` on `authStateChanges`, with `change.mfa!.factors`, and stores no session. Finish it with `orvano.client.completeMfa(MfaAnswer.totp(code))` (or `MfaAnswer.recoveryCode(code)`, or `MfaAnswer.passkey()`). The second step is kept in memory only, so restarting the app starts the sign in over. `confirmTotp` and `verifyMfa` on the client keep the stronger access token they get.

When the project [requires MFA](/docs/auth/mfa/#require-mfa-for-every-user), `enrollmentRequired(result)` says a sign in must enroll a first factor; `orvano.client.startTotpEnrollment()`, `completeTotpEnrollment(code)`, and `enrollPasskey()` do it with the ticket the client holds, and store the session at the end.

## Guests

`orvano.account.createAnonymousSession()` signs a [guest](/docs/auth/anonymous-users/) in and stores the session. `orvano.account.upgradeAnonymous(...)` gives them an email and password and refreshes the session once they are permanent; while the project requires verified emails it answers `verificationRequired: true` and stores nothing.

## Passkeys

`orvano_flutter` has no passkey code of its own, so apps that don't use passkeys start on the web with no extra script. To use them, add `orvano_flutter_passkeys` and pass `PlatformPasskeys()` as `createClient`'s `passkeys`:

<Code code={`flutter pub add orvano_flutter_passkeys:${version}`} lang="sh" />

```dart
final orvano = Orvano(
  createClient(endpoint: 'https://orvano.example.com', project: 'your-project-id', passkeys: PlatformPasskeys()),
);
```

It uses Apple's AuthenticationServices on iOS and macOS, Credential Manager on Android, and Corbado's script on the web, which you serve from your app's `web/` folder. Without it, `signInWithPasskey`, `registerPasskey`, and a passkey answer throw an `ArgumentError` that names the package. [Passkeys](/docs/auth/passkeys/#flutter) walks through Associated Domains, `assetlinks.json`, and the web script.

## Errors

Refused calls throw `OrvanoException` with `status`, `code`, `message`, `requestId`, and `retryAfter`. Match on `code` with the `ErrorCode` constants:

```dart
try {
  await orvano.account.createPasswordSession(
    CreatePasswordSessionRequest(email: email, password: password),
  );
} on OrvanoException catch (error) {
  if (error.code != ErrorCode.invalidCredentials) rethrow;
  // show "Wrong email or password"
}
```

A timeout throws `TimeoutException` instead. See [Errors](/docs/concepts/errors/).
