## Why it happens

The new password is on the list of common passwords Orvano keeps on your server (the most used passwords from public breaches, such as `password1234`). The project refuses them, which is on by default, because attackers try these first. The check is case insensitive. Passwords people already have keep working; it applies only at sign up, on a password change, on a reset, and when a server creates a user.

## How to fix

Ask the person for a password that is harder to guess, such as a few unrelated words. Show the refusal next to the password field, not as a generic error. If your project really needs to allow these passwords, turn off **Refuse common passwords** on the Passwords card of the project's **Security** page in the console.
